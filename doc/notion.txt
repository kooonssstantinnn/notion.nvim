1. INTRODUCTION                                                 *notion-intro*

notion.nvim downloads the Notion pages shared with an integration as markdown
files. You edit them like any other file. |:w| saves locally only; nothing is
sent to Notion until you run |:Notion-publish|.

Publishing sends only the top-level blocks you changed, so comments and block
links on untouched parts of the page survive. If the page was edited in Notion
since your last sync you are asked before anything is overwritten.

Requirements: Neovim 0.10+ and `curl`.

==============================================================================
2. SETUP                                                        *notion-setup*

1. Create an integration at https://www.notion.so/profile/integrations
   (New integration) and copy the Internal Integration Secret.
2. In Notion, open each page you want to edit, then `⋯` > Connections and add
   your integration. Sub-pages are included automatically.
3. Install the plugin, e.g. with lazy.nvim: >lua
     { "kooonssstantinnn/notion.nvim", cmd = "Notion", opts = {} }
<   Without a plugin manager, call: >lua
     require("notion").setup({})
<4. In your project run `:Notion login`, then `:Notion sync`, then `:Notion`.

Run `:checkhealth notion` if something doesn't work.

==============================================================================
3. LOGIN                                                        *notion-login*

Logins are per folder: each project (its |notion-sync_dir|) can use a
different integration or workspace. `:Notion login` asks for the secret,
checks it with Notion, and saves it for the current folder only.

Tokens are stored in `stdpath("state")/notion/auth.json` with mode 0600,
never inside the project.

Token precedence:
  1. the `token` option of |notion-config|
  2. the current folder's login
  3. the environment variable named by `token_env` (`$NOTION_TOKEN`)

OAuth is not supported.

4. COMMANDS                                                  *notion-commands*

:Notion                                                              *:Notion*
:Notion ui              Toggle the dashboard. See |notion-dashboard|.

:Notion open                                                    *:Notion-open*
                        Pick a synced page. `●` marks unpublished changes.

:Notion sync                                                    *:Notion-sync*
                        Download pages changed in Notion, including pages
                        whose sub-pages were added or renamed. Pages with
                        unpublished local edits are skipped, never
                        overwritten. In "only pages I already have" mode
                        (`S` in the dashboard, or `sync_all = false`) only
                        pages you already pulled are updated, plus new
                        sub-pages created under them in Notion.
                        Pages deleted, archived or no longer shared in
                        Notion are removed locally after checking each one
                        with Notion. Files with unpublished edits are kept.
                        Removing 10+ pages and half the folder asks first.

:Notion get[!] [url|id|title]                                    *:Notion-get*
                        Pull one page instead of everything. A URL or ID is
                        used directly; any other text searches Notion by
                        title and lets you pick. If the page has sub-pages
                        you're asked whether to pull them too (nested ones
                        included); [!] pulls them without asking. The page
                        is added to Working.

:Notion search [text]                                         *:Notion-search*
                        Quickfix list of lines in pulled pages matching
                        `text`. Every word must appear in the page (title
                        or content); lowercase ignores case. `n` jumps
                        between matches afterwards.

:Notion work                                                    *:Notion-work*
                        Add the current page to Working, or remove it.

:Notion publish                                              *:Notion-publish*
                        Push the current buffer to Notion. Shows how many
                        blocks will be added and removed and asks to confirm
                        (see `confirm_publish`). A file without `notion_id`
                        creates a new page; you pick the parent page.

:Notion pull[!]                                                 *:Notion-pull*
                        Re-download the current page. Asks before discarding
                        local edits unless [!] is given.

:Notion diff                                                    *:Notion-diff*
                        Side-by-side diff: Notion (left) vs local (right).

:Notion status                                                *:Notion-status*
                        Quickfix list of every page with unpublished changes.

:Notion new [title]                                              *:Notion-new*
                        Create a local draft. It is created in Notion on the
                        first publish.

:Notion browse                                                *:Notion-browse*
                        Open the current page in the browser.

:Notion login                                                  *:Notion-login*
:Notion logout                                                *:Notion-logout*
                        Save or remove the token for the current folder.

5. DASHBOARD                                                *notion-dashboard*

`:Notion` opens a lazygit-style layout:

  [1] Status       login (`● workspace · integration` or `○ Not logged in`),
                   page counts, last sync time and folder
  [2] Working      the pages you're working on, with their sub-pages.
                   Saved per folder. The dashboard opens here when it
                   has pages.
  [3] Pages        the page tree; `M` = unpublished changes, `A` = new draft,
                   `★` = in Working. While searching it lists the matches.
  [4] Unpublished  everything waiting to be published
  [0] Preview      the page, or a diff against the last sync when it has
                   local edits (computed locally, no API call)

Keys ~
  <CR> / e      open the page (at the first match while searching)
  /             search pages by title and content as you type
  g             get one page from Notion (see |:Notion-get|)
  w             add the page to Working, or remove it
  p             publish
  s             sync
  S             sync mode: all pages, or only pages you already have.
                Saved per folder; shown in the Status panel
  P             pull this page
  d             diff with the live Notion page in the preview panel
  <Esc>         leave the diff, clear the search, or close the dashboard
  D             full-screen side-by-side diff
  n             new draft
  o             open in browser
  L             log in for this folder
  r             refresh
  <Space> / za  toggle fold; h / l collapse / expand
  1 2 3 4 0     focus a panel; <Tab> / <S-Tab> cycle panels
  ?             help
  q             close

Prompts open as a small modal in the center: `j` / `k`, arrows or numbers to
choose, <CR> to confirm, <Esc> to cancel.

6. FILES AND FOLDERS                                            *notion-files*

Pages are stored in `notion/` at the project root (the git root of the
current directory, or the current directory itself). The folder is created on
the first sync or new draft. Add `/notion/` to your project's `.gitignore` if
the pages shouldn't be committed.

  notion/
  ├── Page.md
  ├── .notion-index.json    page IDs and sync state
  └── .notion/base/         last-synced copies used for diffs

Each file starts with frontmatter: >markdown
  ---
  notion_id: 1a2b3c4d-...
  title: Project plan
  url: https://www.notion.so/...
  ---
<Edit `title:` to rename the page on the next publish. For a new draft, set
`parent:` to a page URL or ID to choose where it is created.

Any markdown file can be published, not only files in the sync folder.

7. CONFIGURATION                                               *notion-config*

Defaults: >lua
  require("notion").setup({
    token = nil,                -- string or function; overrides the login
    token_env = "NOTION_TOKEN", -- fallback when the folder has no login
    sync_dir = nil,             -- default: <project root>/notion
    default_parent = nil,       -- page URL/ID for new pages (asked if nil)
    confirm_publish = true,
    notify_on_save = true,      -- one-time "saved locally" hint per buffer
    sync_on_startup = false,
    sync_all = true,            -- default sync mode (`S` overrides per folder)
    filter = nil,               -- fun(page): boolean
  })
<
                                                             *notion-sync_dir*
`sync_dir` may be a string or a function returning a path. It is evaluated on
every use, so it follows |:cd|. Set it to `"~/notion"` for one global folder.

Read the token from a password manager: >lua
  token = function()
    return vim.fn.system({ "op", "read", "op://Private/Notion/credential" })
  end,
<

8. MARKDOWN MAPPING                                          *notion-markdown*

  Headings 1-3          `#`, `##`, `###` (`####+` becomes heading 3)
  Inline styles         `**b**` `*i*` `~~s~~` `` `c` `` `<u>u</u>`
  Links, mentions       `[text](url)`
  Lists                 `-`, `1.`, `- [ ]` / `- [x]`, nested by indentation
  Toggle                `▸ Title` with indented children
  Quote / callout       `> text` / `> [!NOTE] 💡` followed by `> text`
  Code                  fenced blocks with a language, including `mermaid`
  Equation              `$$ … $$` block, `$x$` inline
  Table                 pipe table, first row is the header
  Divider               `---`
  External image        `![caption](https://…)`
  Empty block           one extra blank line per empty block
  Anything else         `<!-- notion:keep <id> <type> -->`

Keep placeholders stand for blocks markdown can't represent (sub-pages,
databases, uploaded files, …). Keep the line to keep the block; deleting it
removes the block on publish. Blocks added in Notion since your last sync are
never removed.

Links must be full URLs. On publish `www.…` gets `https://`, a page ID
becomes its Notion URL, and a relative link to another synced `.md` file
becomes that page's URL. Other links are published as plain text with a
warning. Local image paths are published as text.

Text and background colors are not represented. Blocks you don't edit keep
them; blocks you edit are recreated without them.

9. EVENTS AND API                                              *notion-events*

|User| autocmds:

  NotionSynced      after `:Notion sync`
  NotionPulled      after a page is re-downloaded; data = { id, buf }
  NotionPublished   after a successful publish; data = { id, buf }
  NotionLogin       after login or logout
  NotionWorking     after `:Notion work`; data = { doc, working }

Example: >lua
  vim.api.nvim_create_autocmd("User", {
    pattern = "NotionPublished",
    callback = function(ev) print("published " .. ev.data.id) end,
  })
<
                                                           *notion.statusline()*
require("notion").statusline()
    Returns `Notion ✓` (published), `Notion ●` (unpublished changes),
    `Notion ＋` (new draft) or `""` for other buffers.

==============================================================================
10. LIMITS                                                     *notion-limits*

- Notion's API can't insert before the first block of a page. Adding content
  above everything else rewrites the whole page, which loses its comments.
- Changes are diffed per top-level block. Editing one item of a nested list
  recreates that top-level item with its children.
- Database properties other than the title are not synced.
- Notion reports `last_edited_time` to the minute, so two edits in the same
  minute may not be flagged as a conflict.
